The Problem

One Keyword, Too Many Kinds of Risk

unsafe means one precise thing: the compiler can’t prove the absence of undefined behaviour. But it’s Rust’s only machine-checked "needs scrutiny" flag — so it ends up covering:

  • Memory safety violations
  • Custom allocation behaviour
  • Uncontrolled I/O
  • Raw-pointer access

Rust → Rusty

Ten-plus years nightly-only, blocked on one yes/no question about one keyword. Not a knock on Rust’s core safety guarantees — a knock on asking a single binary flag to settle debates it was never built for.

Why It Matters Now

The AI Programming World

AI assistants draft a growing share of production Rust. When a task needs raw performance, FFI, or systems control, the only lever stable Rust gives them is unsafe.

That block conflates a raw pointer, a custom allocator, and uncontrolled I/O into one yes/no signal — right as review time per line is going down and code volume is going up.

Review capacity, not generation speed, is the actual bottleneck.

The Orthogonal Fix

capability-attr

Sidestep the stalled debate instead of waiting for it. Stable Rust, compile-time, today:

#[capability(alloc(pool = "arena"), io(none), ptr(none))] fn build_response(req: &Request) -> Response { // Compiler-enforced: only "arena" allocation. // Any I/O or raw pointer here is a compile error. ... }

The Orthogonal Fix

sensitive-ifc

The same move, one layer up — for data classification instead of side-effect scope.

let ssn: Sensitive<String, Restricted> = Sensitive::new(raw); // error[E0277]: Sensitive<String, Restricted> // does not implement Display println!("{}", ssn);

A compile error, not a code-review hope.

Defense in Depth

Where This Ends

Compile-time (this project)

Catches: a function exceeding its declared alloc/io/ptr scope — in code built with the attribute applied.

Can’t see: a compromised binary, a dependency that skipped the attribute, any other process on the host.

Runtime, OS-enforced (AppArmor / SELinux)

Catches: what any process actually does at the syscall boundary — regardless of source language.

Can’t see: which internal function allocated what — no notion of intra-process scope.
